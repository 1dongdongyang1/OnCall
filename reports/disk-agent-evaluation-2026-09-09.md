- Runtime：工具预算、规范化参数去重、工具与模型超时、Agent 总超时、明确终止原因、usage 缺失。
- 磁盘业务：真实告警、告警恢复、日志异常增长、备份占用、工具失败、SOP 无匹配。
- 安全：节点边界、证据 ID、告警状态与现场数值一致、SOP 非授权、无自动清理/重启、业务归属未知时要求 RD/负责人确认。

## 迭代中发现并修正的问题

1. 首次真实运行中，模型常在 JSON 前输出自然语言，导致 5 个正常完成的案例无法整段解析。解析器现只选择语法完整且包含诊断契约字段的 JSON 对象，之后仍执行完整证据校验。
2. 一次真实输出把工具返回的 `usedGb=95` 写成“已用 91GB”。因此增加带单位数值的现场证据校验；无来源的容量或百分比会使报告验收失败。该次错误输出不计为成功案例。
3. 原评测对“未知/未提供/无法确认”和“SOP 未匹配/未命中”的措辞要求过窄。现改为语义等价判断，同时保留节点、工具、证据、状态、安全和升级约束。
4. SOP 原始 Chunk 可能包含变更命令。结构化报告只暴露 SOP 的文档名、标题路径、Chunk ID、来源路径与分数，不回显 Chunk 原文，并固定标记 `authorization=false`。

## 当前结论

固定 Mock 下，磁盘告警确认、逐层定位、文件性质分析、结构化报告和工具失败升级闭环已经建立。真实模型对五类路径达到当前行为门槛；SOP no-match 后的改写重试仍需在下一轮通过受控策略或更强的单次查询约束解决，不能视为已经通过。
