# 真实只读磁盘数据源最小设计

## 目标与边界

下一阶段只新增一个 `DiskInspectionSource` 实现，并在 `src/index.ts` 组合根替换当前 Mock。工具名称、参数和结构化报告契约保持不变。数据源只收集磁盘容量、直接子项占用和已定位文件的有限元数据，不执行删除、清空、截断、重启、扩容、隔离或权限修改。

## 命令白名单

禁止拼接 shell 字符串，使用 `spawn(executable, args, { signal, shell: false })`。每个接口只允许固定可执行文件和固定参数模板；`node`、挂载点和路径作为独立参数传入并先经过范围校验。

| DataSource 方法 | 允许命令模板 | 用途 |
| --- | --- | --- |
| `getDiskUsage` | `df -B1 --output=source,size,used,avail,pcent,target -- <mountPoint>` | 读取指定挂载点容量和使用率 |
| `listLargeDirectories` | `du -x -B1 --max-depth=1 -- <path>` | 只统计指定目录的直接子项，不跨文件系统 |
| `inspectFile` | `stat --printf=<fixed-format> -- <path>` | 读取大小、属主、类型和修改时间 |
| `inspectFile`（可选日志观察） | `tail -n <fixed-limit> -- <path>` | 仅对已由目录证据定位、且符合允许日志根目录的普通文件读取有限尾部 |

白名单不包含通用 shell、脚本解释器、包管理器、服务管理器或任何带写入语义的子命令。路径必须是规范化绝对路径；拒绝 NUL、父目录逃逸、符号链接越界和不在该节点允许根目录内的目标。`inspectFile` 只能检查前序目录结果中 `kind=file && inspectable=true` 的精确路径。

## 节点与权限

- 由服务端维护 `node -> transport target -> read-only credential -> allowedRoots` 清单，不能从模型参数推导主机地址或凭证。
- 告警中的节点必须精确命中清单；一次诊断创建不可变的节点上下文，所有机器工具复用它。
- 远端账户仅授予读取文件系统统计、目录大小和受限文件元数据所需权限；不授予 sudo、写权限或服务控制权限。
- 日志尾部读取采用额外路径白名单和最小权限；默认关闭，只有业务确认数据分类与脱敏规则后开启。

## 超时与取消

- 将 Runtime 传入的同一个 `AbortSignal` 继续传给本地 `spawn` 或远端执行客户端。
- 超时时先取消远端请求并终止子进程树，等待进程退出确认；在退出确认前不把调用标记为完成。
- abort 后丢弃迟到输出，不解析、不缓存，也不允许触发新的目录或文件检查。
- 分别设置连接超时、命令超时和总诊断超时；超时返回类型化失败，由现有 Runtime 以 `tool_timeout` 安全终止并生成人工升级报告。

## 输出限制

- 单次进程 stdout 与 stderr 各设硬上限，建议 1 MiB；超过即取消并返回 `output_limit_exceeded`，不得静默截断后形成确定性结论。
- 目录结果最多保留按字节数降序的 256 个直接子项；原始路径长度、单行长度和总条目数均设上限。
- 可选日志尾部最多 200 行且不超过 64 KiB；在进入 Tool Result 前执行密钥、令牌、Cookie 和常见个人信息脱敏。
- 数值统一以字节解析，再在 DataSource 边界转换为报告使用的单位；解析失败或输出不完整时返回错误，不以 0 代替。

## 审计日志

每次调用记录不可变的结构化审计事件：`runId`、`alertId`、`toolCallId/evidenceId`、调用者、节点、规范化路径、白名单命令 ID、开始/结束时间、超时配置、退出码、取消原因、输出字节数、是否截断、结果摘要哈希和最终终止原因。审计日志不保存文件正文或凭证；敏感路径按既定规则脱敏。

## 接入顺序

1. 实现 `RealDiskInspectionSource`，保持现有接口不变，并用可控假进程验证参数数组、路径边界、取消和输出上限。
2. 在独立只读测试节点验证三种命令模板和权限最小化，不接生产流量。
3. 将真实实现作为组合根配置项，Mock 仍用于默认测试和 Agent 业务评测。
4. 先影子运行并比对人工结果与结构化报告；确认审计、超时和脱敏后再接告警入口。
